# ASCEND\_COREDUMP\_SIGNAL

<!-- md-trans-meta sourceCommit=c8ac86bc9670f985eed4317df3ede8668c96fea6 translatedAt=2026-10-22T09:25:28.104Z pushedAt=2026-10-23T07:25:36.623Z -->

## Description

Sets whether trace registers the signal handling functions for recording abnormal stacks.

The value can be:

- `none`: trace does not register the handling functions for the signals listed in Table 1.
- Other values than `none`: trace registers the handling functions for the signals listed in Table 1.

By default, trace registers the handling functions for the signals listed in Table 1. When a process triggers these signals, trace records the abnormal stack information in the `stackcore_tracer_*.txt` file.

**Table 1** Signal set

| Signal | Value |
| --- | --- |
| SIGINT | 2 |
| SIGQUIT | 3 |
| SIGILL | 4 |
| SIGTRAP | 5 |
| SIGABRT | 6 |
| SIGBUS | 7 |
| SIGFPE | 8 |
| SIGSEGV | 11 |
| SIGTERM | 15 |
| SIGXCPU | 24 |
| SIGXFSZ | 25 |
| SIGSYS | 31 |
| SIGRTMIN+1 | 35 |

If the service itself also needs to register the handling functions for the signals listed in Table 1 (for example, using JVM signal capture), it may conflict with the signal handling functions of trace. After the signal handling function registration of trace is disabled, if the service triggers a core dump, trace does not generate the abnormal stack file. You need to locate the problem using other methods.

## Configuration Example

```sh
export ASCEND_COREDUMP_SIGNAL=none
```

## Constraints

None

## Supported Models

Supported on all chips.
