## Log Classification

Logs are mainly used to record the system running process and exception information, helping users quickly locate problems that occur during system running and program debugging issues during development. Logs are classified as follows:

- **System logs**: logs generated on the device side when the system is running. They mainly include:
  - System logs on the control CPU, including kernel-mode logs and user-mode logs generated by system process running, which mainly reflect the overall running status of the AI processor.
  - System logs on non-control CPUs (for example, low power consumption), which mainly reflect the running status of components such as low power consumption, Task Scheduler, and ISP.

- **Application logs**: logs generated when AI applications are running. They mainly include:
  - Logs printed by components such as AscendCL, GE, Runtime, and HCCL on the host side.
  - Logs printed by the AI CPU process on the device side.

In the log file names mentioned in this document, `id` and `pid` represent the device ID and service process ID respectively, which are subject to the actual values.

During program running, the maintenance and test information of the software stack is also recorded in the memory. When a program error occurs or the process ends, this information is stored to files, so as to avoid frequently generating and recording log files during program running, which affects performance. This information is stored in trace logs. The trace log generation mechanism is relatively independent. For details, see [Viewing Trace Logs](viewing_trace_logs.md).

## Log Recording Format

The following is a log sample:

```sh
[ERROR] TEFUSION(12940,atc):2021-10-17-05:54:07.599.074 [tensor_engine/te_fusion/pywrapper.cc:33]InitPyLogger Failed to import te.platform.log_util
```

The log format is as follows:

```sh
[Level] ModuleName(PID,PName):DateTimeMS [FileName:LineNumber]LogContent
```

**Table 1**  Log Field Description

|Field|Description|
|--|--|
|Level|Log level, which can be one of the following: **ERROR**, **WARNING**, **INFO**, **DEBUG**.|
|ModuleName|Name of the module that generates the log.|
|PID|Process ID of the module.|
|PName|Process name of the module.|
|DateTimeMS|Time when the log is printed, in the format of *yyyy-mm-dd-hh:mm:ss.fff.zzz*.|
|FileName:LineNumber|File that calls the log printing API and the corresponding line number.|
|LogContent|Specific log content of each module.|
