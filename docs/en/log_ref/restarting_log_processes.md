# Restarting Log Processes

<!-- md-trans-meta sourceCommit=31ae292a88c1a38674abaa350b60eba724bab178 translatedAt=2026-10-22T09:33:39.883Z pushedAt=2026-10-23T10:40:48.603Z -->

After modifying the log configuration file on the device side, you need to restart the log process for the configuration to take effect. You must have the permission to log in to the device side before you can restart the log process on the device side.

After the process is restarted, the system logs determine whether the capacity of the previous log file has reached the upper limit. If the upper limit has not been reached, newly generated system logs continue to be written to the previous log file. Log information generated by application logs is written to a new log file (even if the size of the previous log file has not reached the specified value).

<!-- npu="310p" id1 -->

## Control CPU Open Form

1. Run the following command to stop the log process:

    `kill -15 process ID`

    The ID of the process (**slogd**, **sklogd**, or **log-daemon**) can be queried by running the `ps -elf | grep log` command.

    Use `kill -15` to stop the **slogd** process so that it cleans up the shared memory when it receives the termination signal. If `kill -15` fails repeatedly, use `kill -9` to forcibly stop the log process.

2. Restart the log process.

    The log process restarts automatically, and no manual startup is required.

    After a period of time, you are advised to run the `ps -elf | grep log` command to check whether the restart is successful. If the restart fails, obtain the logs and click [support](https://www.hiascend.com/support) to contact technical support.

<!-- end id1 -->

## Ascend RC Form

1. Run the following command to stop the log process:

   `kill -15 process ID`

    The process (**slogd**, **sklogd**, or **log-daemon**) ID can be queried using the `ps -elf | grep log` command.

    Use `kill -15` to stop the slogd process so that it cleans up the shared memory when it receives the termination signal. If `kill -15` fails repeatedly, use `kill -9` to forcibly stop the log process.

2. Restart the log process.

    <!-- npu="310b" id3 -->
    For Atlas 200I/500 A2 inference products, the log process restarts automatically, and no manual startup is required.
    <!-- end id3 -->

    After a period of time, you are advised to run the `ps -elf | grep log` command to check whether the restart is successful. If the restart fails, obtain the logs and click [support](https://www.hiascend.com/support) to contact technical support.

## Restart Exception Handling

If restarting the log process fails, it may be caused by high disk usage on the disk where the **/var** directory resides. Handle it as follows:

Go to the root directory and run the `df -h` command. If the disk usage of the disk where the **/var** directory resides reaches 100%, causing **slogd** startup to fail, go to the **"/var/log/npu/slog"** directory and manually delete some large, older log files. After the deletion is complete, restart the log process.
