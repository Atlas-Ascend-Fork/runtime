# Viewing Logs (Control CPU Open Form)

<!-- md-trans-meta sourceCommit=490980fac47f296083b7cdba2f59604a84255da6 translatedAt=2026-10-22T09:37:39.782Z pushedAt=2026-10-23T09:13:06.602Z -->

This topic describes the log file storage paths and the main information recorded in each log file in the control CPU open form.

The log-related description is as follows:

- Application logs support aging. By default, each log type (debug, run, and security) supports storing 24 `device-app-pid` directories. The system scans these directories every 15 seconds. If the logs exceed the configured storage limit, the earliest `device-app-pid` directory is automatically deleted.

  For details about the configuration of the number of stored `device-app-pid` directories, the number of log files stored in each `device-app-pid` directory, and the size of a single log file, see [Viewing the Log Configuration File](viewing_config_file.md).

- A maximum of 24 application processes can be handled concurrently. If this value is exceeded, logs may be lost.

**Table 1**  Log file description

|Storage Path|Description|
|--|--|
|`/var/log/npu/slog/debug/device-app-pid/device-app-pid_*.log`|Debug logs generated by application processes on the control CPU.|
|`/var/log/npu/slog/run/device-app-pid/device-app-pid_*.log`|Run logs generated by application processes on the control CPU.|
|`/var/log/npu/slog/security/device-app-pid/device-app-pid_*.log`|Security logs generated by application processes on the control CPU.|
|`/var/log/npu/slog/slogd/slogdlog`|Maintenance and test logs, which record the running information of the log tool itself for locating problems of the log tool. The logs have an aging policy. When the size of the **slogdlog** file reaches the specified size (1 MB), its name is changed to **slogdlog.old** for backup (if a backup file already exists, the earliest backup file is deleted).|
|The following files need to be exported and viewed by logging in to the host-side server and using the msnpureport tool. For details about how to use the tool, see [msnpureport Tool User Guide](https://support.huawei.com/enterprise/en/ascend-computing/ascend-hdk-pid-252764743?category=reference-guides&subcategory=command-reference).| -|
|`/var/log/npu/slog/debug/device-os/device-os_*.log`|Debug logs generated by system processes on the control CPU, including user-mode logs and kernel-mode logs.|
|`/var/log/npu/slog/run/event/event_*.log`|Event logs generated by system processes on the control CPU.|
|`/var/log/npu/slog/run/device-os/device-os_*.log`|Run logs generated by system processes on the control CPU.|
|`/var/log/npu/slog/security/device-os/device-os_*.log`|Security logs generated by system processes on the control CPU.|
|`/var/log/npu/slog/debug/device-id/device-id_*.log`|System logs on non-control CPUs, mainly collecting logs from the TS, TSDUMP, and LP modules.|

In the preceding logs, `id` and `pid` represent the device ID and process ID respectively, subject to the actual values. The `*` in a log file name indicates the timestamp when the log file is created.
