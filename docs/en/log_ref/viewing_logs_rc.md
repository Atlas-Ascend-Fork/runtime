# Viewing Logs (Ascend RC)

<!-- md-trans-meta sourceCommit=74980743e3b09c54b71b1fd8f54f08365f306efe translatedAt=2026-10-22T09:38:15.355Z pushedAt=2026-10-23T09:12:55.641Z -->

This topic describes the storage paths of log files and the main information recorded in each log file in Ascend RC mode.

Logs support aging. If logs exceed the configured storage limit, the earliest log directory or file is automatically deleted. For details about the number of log directories or files and the size of a single log file, see [Viewing the Log Configuration File](viewing_config_file.md).

**Table 1** Log file description

|Storage Path|Description|
|--|--|
|`/var/log/npu/slog/debug/device-os/device-os_*.log`|Debug logs generated by system processes on the control CPU, including user-mode logs and kernel-mode logs.|
|`/var/log/npu/slog/debug/device-app-pid/device-app-pid_*.log`|Debug logs generated by application processes on the control CPU.|
|`/var/log/npu/slog/run/event/event_*.log`|Event logs generated by system processes on the control CPU.|
|`/var/log/npu/slog/run/device-os/device-os_*.log`|Run logs generated by system processes on the control CPU.|
|`/var/log/npu/slog/run/device-app-pid/device-app-pid_*.log`|Run logs generated by application processes on the control CPU.|
|`/var/log/npu/slog/security/device-os/device-os_*.log`|Security logs generated by system processes on the control CPU.|
|`/var/log/npu/slog/security/device-app-pid/device-app-pid_*.log`|Security logs generated by application processes on the control CPU.|
|`/var/log/npu/slog/debug/device-id/device-id_*.log`|System logs on non-control CPUs, mainly collecting logs from the TS, TSDUMP, and LP modules.|
|`/var/log/npu/slog/slogd/slogdlog`|Maintenance and test logs, which record the running information of the log tool itself for locating issues of the log tool. The log has an aging policy. When the size of the **slogdlog** file reaches the specified size (1 MB), it is renamed to **slogdlog.old** for backup (if a backup file already exists, the earliest backup file is deleted).|

In the preceding logs, `id` and `pid` represent the device ID and process ID respectively, subject to the actual values. The `*` in a log file name indicates the timestamp when the log file is created.
